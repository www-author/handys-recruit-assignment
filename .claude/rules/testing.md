# 테스트 지침

## 단위 테스트

- 판정 정책은 Spring 컨텍스트 없이 테스트한다. 고정 Clock과 명시적인 예약·청소 상태를 사용한다.
- 정상·제외 사례와 정확한 시간 경계를 함께 다룬다. 60분 경계 초과 여부는 초 단위의 명시적 예제로 검증한다.
- 서울 자정 전후와 UTC 날짜가 다른 시각을 포함하여 시스템 기본 시간대에 의존하지 않음을 확인한다.
- 예정 시각이 현재와 같은 경우, 이미 지난 경우, 다른 날짜인 경우를 구분한다.
- 검증 가능한 입력·기대값을 코드에 명시한다. Thread.sleep이나 실제 현재 시각, 테스트 실행 순서에 의존하지 않는다.

## 통합 테스트

- Spring Boot Test·MockMvc와 H2로 HTTP 계약 및 저장 상태를 함께 검증한다. 이 단계에서 Repository를 목으로 대체하지 않는다.
- 조회 → 완료 → 재조회 흐름, 없는 작업·잘못된 ID, 빈 목록·정렬, 청소 작업 없음, 반복 완료를 확인한다.
- 동시 완료는 서로 다른 트랜잭션과 동기화 장벽으로 요청을 겹치게 하고 모든 작업 종료를 확인한다. 두 응답 및 최종 DB의 최초 완료 시각이 일치해야 한다.
- 고정 시각 하나만 사용하는 동시성 테스트는 타임스탬프 덮어쓰기를 놓칠 수 있다. 서로 다른 시각을 제공하는 제어 가능한 Clock으로 덮어쓰기가 드러나게 검증한다.
- 동시 요청용 데이터는 실행 전에 커밋한다. 테스트의 롤백 전용 트랜잭션에 데이터를 숨기지 않는다. 테스트별 데이터를 격리한다.
- H2 통과를 MySQL·PostgreSQL의 잠금·SQL 호환성 검증으로 주장하지 않는다.

## 실행과 보고

- Wrapper가 생긴 뒤 관련 테스트를 실행하고 제출 전 `./gradlew test`를 실행한다. 빌드 설정 변경 시 필요한 빌드 확인도 수행한다.
- README에 실제 명령과 결과를 간략히 기록한다. 실행하지 못했다면 사유와 미검증 범위를 밝힌다.
- 문서만 변경할 때는 참조와 일관성을 검사한다. 문서 검사를 애플리케이션 테스트 통과로 표현하지 않는다.
