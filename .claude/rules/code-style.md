# Kotlin·Spring 코드 지침

## Kotlin

- 들여쓰기는 공백 4칸으로 통일한다. 파일·코드 식별자는 영어, 설명과 문서는 한국어로 작성한다.
- `val`과 불변 컬렉션을 우선한다. 엔티티 상태 변경은 의도한 도메인 동작이나 조건부 저장 연산으로 제한한다.
- nullable 타입으로 부재를 표현하고 명시적으로 처리한다. `!!`로 검증을 우회하지 않는다.
- DTO에는 data class를 사용하되 JPA 엔티티에는 사용하지 않는다. 자동 equals·hashCode·toString이 지연 로딩과 변경 가능한 상태에 의존하지 않도록 한다.
- 상태와 사유는 enum 등 명시적인 타입으로 표현한다. 이해하기 어려운 scope function 중첩과 범용 유틸리티를 피한다.

## Spring·API

- 생성자 주입을 사용한다. 필드 주입을 하지 않는다.
- 비즈니스 판정은 Controller에 두지 않는다. 응답 DTO는 API에 필요한 데이터만 노출한다.
- 외부 입력은 경계에서 검증한다. Kotlin의 Validation 애너테이션 적용 위치를 확인하고 실제 잘못된 요청으로 테스트한다.
- 예외를 삼키거나 오류를 정상 응답으로 바꾸지 않는다. HTTP 오류 변환은 일관된 예외 처리 지점에서 수행하고 내부 스택·SQL을 응답에 노출하지 않는다.
- 도메인 로직에서 `Instant.now()`, `LocalDate.now()`를 직접 호출하지 않는다. 주입된 Clock에서 요청당 한 번 얻은 시각을 전달한다.
- 정렬 조건과 경계 포함 여부를 코드에 명시한다. DB의 우연한 반환 순서에 의존하지 않는다.
- 주석은 선택 이유와 제약을 설명한다. 코드 자체를 반복하는 주석이나 구현되지 않은 기능을 약속하는 설명은 쓰지 않는다.
